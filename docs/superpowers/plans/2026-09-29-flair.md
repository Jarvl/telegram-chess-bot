# Flair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players earn emoji flair from games that finish after each flair ships, wear up to three
beside their name everywhere in the Mini App, and choose them on a Flair screen opened from
Settings.

**Architecture:** A data-only catalog in `packages/shared` (id, emoji, category, typed rule
descriptor) is interpreted on the server by two exhaustive registries: move-pattern detectors and
rule evaluators. An `award_flair` job, enqueued when a game against a person ends, scores that game
for both players and fills free worn slots. `PlayerRef.flair` carries worn ids to every screen; the
Mini App draws them with one `<Flair>` component and edits them on the Flair screen.

**Tech Stack:** TypeScript 6, zod 4, Drizzle ORM on PostgreSQL 18, Hono, the table-backed job
queue, Preact with `@preact/signals`, Vitest (happy-dom for the app), Playwright.

**Spec:** `docs/superpowers/specs/2026-09-29-flair-design.md`

## Global Constraints

- Ids, emoji (code point for code point), categories, rules and descriptions exactly as spec §1.2. Ids are permanent.
- Counted games (spec §1.3): `status = 'finished'`, `voided_at` null, `result` in `1-0`, `0-1`, `1/2-1/2`, `engine_level` null; ordered by `(finished_at, id)`.
- A rule's answer at a game depends only on that game and the player's earlier counted games (§1.6). Each flair sees only games finished at or after its introduction (§1.5).
- Flair is never removed once earned. There is no backfill and no re-derivation on void, ratings rebuild or rule change.
- At most `MAX_WORN_FLAIR = 3` worn. The bot and deleted players carry no flair.
- Every visible string lives in `packages/shared/src/i18n/en.ts` and goes through `t()`.
- Space emoji with a flex `gap`, never `letter-spacing`, which can split ZWJ sequences such as 🧑‍🦼 (spec §5.1).
- Earned dates use `Intl.DateTimeFormat('en-US')`, month first (spec §5.5): "Jan 2026", "Aug 12", "Dec 30, 2025".
- Colours come only from the redesign's tokens: `--acc`, `--acc-ink`, `--acc-soft`, `--acc-text`, `--page`, `--card`, `--hint`, `--sep`, `--sep-strong`.
- Existing `data-*` hooks keep their names. New hooks: `data-action="flair"`, `data-slot`, `data-flair`.
- Test code below leaves out the `vitest` imports (`describe`, `it`, `expect` and the hooks) and shows the other imports only where a name or path is new. Prettier formats it on commit.
- Run every command from the repository root. Integration tests need this worktree's own database: `docker compose up -d db` (Docker Desktop), `docker compose exec db psql -U postgres -c 'create database group_chess_test_flair'`, then `export TEST_DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/group_chess_test_flair`.
- Every commit message ends with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (the commit steps pass it as a second `-m`).

## Review Focus

1. A long display name wearing three flair on a 390 px phone: the name ellipsises, flair and rating stay whole, and nothing scrolls sideways. Task 9 pins flair as a sibling of `.name`; Task 12 runs the screens spec with a long name and three flair.
2. Two quick taps on the Flair screen whose saves answer out of order: the slots end as the last tap left them. Task 10, "keeps the last tap when saves answer out of order".
3. ZWJ emoji (🧑‍🦼 🧑‍🦽 🧑‍🦯) and ♟️ must each draw as one glyph. Task 9, "draws each known flair whole".
4. One game earning more flair than there are free slots: every award is stored, only the free slots fill, the pick is random, and earlier worn flair keep their places. Task 7, "picks at random…" and "stores every new flair but fills only the free slots…".
5. A streak or total whose n-th game was missed (a failed job, or two games committing out of order) is awarded at the player's next qualifying game. Task 7, "awards a streak it missed at the player’s next rated win".
